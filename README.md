# Expense Approval

MVP сервісу узгодження заявок на відшкодування витрат.
Співробітник подає заявку → вона автоматично йде до погоджувача, відповідального
за цю категорію → погоджувач ухвалює або відхиляє (з обов'язковим коментарем).

FastAPI + PostgreSQL (SQLAlchemy 2.0 + Alembic) + звичайний HTML/JS без збірки.

## Запуск

```bash
# 1. база
docker compose up -d            # Postgres 16 на порту 5434

# 2. залежності
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. налаштування
cp .env.example .env            # за потреби — свій DATABASE_URL і ключ OpenAI

# 4. схема бази
alembic upgrade head

# 5. перший адміністратор
python -m app.cli create-admin --email admin@company.com --name "Ваше ім'я"

# 6. запуск
uvicorn app.main:app --reload
```

Відкрити http://127.0.0.1:8000

Якщо Postgres у вас уже свій — пропустіть крок 1 і вкажіть свій `DATABASE_URL`
у `.env`.

## Як почати працювати

Демо-користувачів у системі немає — усі акаунти справжні.

1. Адміністратор створюється один раз командою з кроку 5.
2. Решта людей **реєструються самі** на головній сторінці і отримують роль
   співробітника.
3. Адміністратор у вкладці «Адміністрування» видає комусь роль погоджувача
   і призначає його на категорії.
4. Поки в категорії немає погоджувача, заявку в неї подати не можна — форма
   показує це прямо, а сервер відповідає `409`.

## Ролі

| Роль | Що може |
|---|---|
| `employee` | подавати заявки, бачити свої, відкликати нерозглянуті |
| `approver` | бачити свою чергу, погоджувати та відхиляти |
| `admin` | керувати ролями і маршрутизацією «категорія → погоджувач» |

Ролі не виключні: одна людина може бути і співробітником, і погоджувачем —
для невеликої організації це нормально.

## Тести

```bash
docker compose up -d    # тести ходять у справжній Postgres
pytest -q               # 35 тестів
```

Тести створюють окрему базу `expense_approval_test`, прогоняються в ній і
прибирають її за собою. Покривають те, що найлегше зламати: маршрутизацію за
категоріями, видимість чужих заявок, обов'язковий коментар при відхиленні,
відкликання лише до рішення, права адміністратора і те, що зламаний AI не
блокує погоджувача.

### База

PostgreSQL, схема описана моделями SQLAlchemy, зміни — через Alembic
(`alembic revision --autogenerate -m "..."`).

Кілька речей винесено на рівень бази, щоб вони трималися навіть в обхід
застосунку:

- `amount_usd` — `NUMERIC(12,2)`, а не float: копійки не «пливуть»;
- CHECK `amount_positive` — сума завжди додатна;
- CHECK `rejected_needs_comment` — відхилену заявку **неможливо** зберегти без
  коментаря;
- `category`, `status`, `role` — справжні PostgreSQL-енами;
- зовнішні ключі з `ON DELETE RESTRICT` на заявках: користувача, в якого є
  заявки, не видалити випадково.

### Статуси

`pending → approved | rejected | withdrawn`. Рішення остаточне. При ухваленні
рядок заявки блокується через `SELECT ... FOR UPDATE`, щоб два одночасні
рішення не розійшлися.

### Маршрутизація

Таблиця `category_approvers`, якою керує адміністратор.
Один нюанс: якщо погоджувач сам подає заявку у «свою» категорію, вона йде до
іншого погоджувача. Сам себе ніхто не погоджує.

Адміністратор не може зняти роль погоджувача з людини, на якій ще висять
категорії — спершу треба передати їх комусь іншому. Інакше заявки не мали б
куди йти.

### Хто що бачить

Заявку бачать рівно двоє: її автор і призначений погоджувач. Стороннім
повертається `404`, а не `403` — щоб не підтверджувати факт існування заявки.

### Паролі й сесії

Пароль зберігається як PBKDF2-HMAC-SHA256, 200 000 ітерацій, із власною сіллю.
Сесія — випадковий токен у таблиці `sessions`, у браузері живе в `httponly`-кукі.

### «Реальний час»

Фронтенд тихо опитує сервер раз на 4 секунди (плюс одразу при поверненні на
вкладку). Для MVP цього достатньо; WebSocket/SSE тут були б зайвою складністю.

## AI-компонент

Коли погоджувач відкриває заявку, `GET /api/claims/{id}/ai-review` просить
OpenAI зробити дві речі: стисло описати заявку (1–2 речення) і сказати, чи
сума/категорія/опис узгоджені між собою. Промпт — у [app/ai.py](app/ai.py),
англійською, зі структурою `<task>` / `<rules>` / `<flag_examples>` /
`<output_format>`, відповідь строго JSON.

Приклад неузгодженості: категорія «Office», а в описі — квиток на літак до
Лондона. AI підніме прапорець і одним реченням пояснить, що саме не збігається.

Що зроблено, щоб AI лишався **допоміжним**:

- він ніколи не ухвалює рішення — у відповіді немає поля «схвалити/відхилити»,
  і в промпті це заборонено прямо;
- ендпоїнт **завжди повертає 200**. Немає ключа, впав OpenAI, вийшов таймаут
  (8 с) — приходить `{"available": false, "reason": "..."}`, і погоджувач бачить
  рядок «рішення ухвалюєте ви — це нічого не блокує»;
- кнопки «Погодити» / «Відхилити» активні одразу, ще до відповіді AI;
- результат кешується в таблиці `ai_reviews` — модель смикається один раз
  на заявку.

Модель за замовчуванням — `gpt-4o-mini`, змінюється через `OPENAI_MODEL`.

## Що свідомо лишилося за межами MVP

Відновлення пароля, вкладення чеків, історія змін заявки, пагінація,
конвертація валют (усе фіксовано в USD), email-сповіщення.
